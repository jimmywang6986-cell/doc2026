# 赛道三 APP 方案：《复途》— 康复治疗师的 AI 分身

> 归口推荐主题：**(4) 数智健康·民生守护**（原文逐字列出「康复训练」）
> 兼顾：**(5) 虚实共生·多态交互**（视觉 + 语音多模态、无障碍交互）、**(2) 数智转型·行业增效**（医疗领域自动化工作流）

## 一、先说一个必须先想清楚的约束

原文对赛道三的技术文档要求是：**系统架构图、核心逻辑说明及提示词（Prompt）设计**。

「提示词设计」是硬性列举项。**这意味着作品必须是一个真正的 Agent，而不是一个计算机视觉应用。** 一个纯姿态估计的动作矫正 App 交不出 Prompt 设计，会在完整性（20%）和规范性（10%）上直接失分，而且跑错了赛道——这是「智能体创新」，不是「计算机视觉」。

这个约束反过来指明了产品的正确形态：**CV 是 Agent 调用的一个工具，Agent 的价值在决策。** 下文所有设计都围绕这一点展开。

### 一句话市场论证

**4.4 万名治疗师，4.6 亿人的康复需求。** 这不是「服务体验不够好」的问题，是**算术上根本不成立**的问题。任何试图靠增加治疗师来解决的路径都会失败——本科起点的康复治疗师至少需要 5 年教育加 1 年从业才能持证。

## 三、竞品：必须先承认一件事

**AI 动作矫正在国内已经不是空白，有在售商业产品和已公开专利。** 参赛前把这一点想清楚，否则复评答辩时被评委一句「霁达云康已经做了」就问倒。

| 竞品 | 形态 | 已做到 |
| --- | --- | --- |
| **霁达云康**（患者端） | 卒中康复品牌的配套 App | AI 动作矫正、摄像头捕捉关节角度、300+ 训练视频库、远程医患互动、语音指导 |
| **对练**（sensfusion） | CV 动作捕捉康复训练系统 | 实时动作捕捉与分析，执行康复师制定的居家计划；明确声明「只作为医生和康复师制定训练计划、监督患者完成情况的工具，不提供诊断功能」 |
| 学术与专利 | OpenPose/MediaPipe 卒中康复评估系统、上肢康复代偿识别专利（埃斯顿医疗）、肩肱协同比例识别耸肩代偿专利、RehabMate 可解释框架 | **连「代偿动作检测」都已有专利和开源实现** |

### 所以「比同类更好」不能靠这三条（都会输）

- 比 CV 精度：打不过有临床数据积累和融资的团队
- 比动作库丰富度：霁达 300+ 视频库，比不过
- 比「有 AI 动作矫正」：已经是行业标配，不是卖点

### 真正的空白在两个地方

**空白一：所有现有产品都是「处方执行器」，没有决策层。**

它们的逻辑是：治疗师开处方 → App 播放动作 → CV 判断做得标不标准 → 数据回传。**中间没有任何判断。** 患者今天疼痛评分升高、动作质量掉了三成、只完成了 60%，是该咬牙坚持、该降级、还是该停下叫医生？这个判断现在必须由治疗师做，而治疗师一周最多看一次。

于是出现一个荒谬的局面：**产品每天采集数据，但每天没人看**。数据攒了一周，治疗师花五分钟翻一遍。

> **现有产品让 AI 当「眼睛」——看你做得标不标准。
> 这个产品让 AI 当「判断」——今天该不该练、练多少、要不要叫人。**
> 眼睛只能提高单次训练质量；判断才能解决 4.4 万治疗师覆盖 4.6 亿人的算术问题。

**空白二：现有产品服务的是「能用 App 的城市患者」。**

霁达、对练的渠道都是三甲医院和康复机构，用户是有医院对接、有支付能力、有家属协助的城市患者。而康复资源最匮乏的是县域和农村——那里的患者出院后基本是零康复。

更尖锐的一点：**康复 App 的目标用户，恰恰是最不能使用 App 的人。** 卒中患者常见偏瘫（一只手拿不稳手机还要点屏幕）、构音障碍（说话含糊，通用语音识别基本失效）、视野缺损、认知障碍。而霁达云康的用户反馈里就有一条真实需求：「希望增加更多方言语音包以覆盖老年群体」。

## 四、产品设计

### 定位

**《复途》—— 康复治疗师的 AI 分身。**

不是又一个动作矫正 App，而是在治疗师设定的处方边界内，替治疗师做日常决策、并在越界时把人叫回来的康复智能体。

### 核心机制：处方边界内自治 + 越界升级

这是全作品的技术与合规核心，一个设计同时解决三个问题。

治疗师在 Web 端设定的不是一份固定处方，而是一个**可活动的边界（treatment envelope）**：

```json
{
  "patient_id": "...",
  "phase": "出院后第 3 周",
  "exercises": [
    {
      "id": "shoulder_abduction",
      "reps": { "min": 10, "target": 15, "max": 20 },
      "rom_deg": { "floor": 45, "target": 70, "ceiling": 90 },
      "compensation_tolerance": { "shrug_deg": 12, "trunk_lean_deg": 10 }
    }
  ],
  "stop_rules": { "pain_nrs": 4, "consecutive_fail_days": 2 },
  "escalate_rules": { "pain_nrs": 6, "quality_drop_pct": 30, "no_activity_days": 3 }
}
```

Agent 在这个框内**每天自主决策**：今天练哪几个动作、做几组、要不要降到 floor、要不要提前收工、用什么话术鼓励。一旦触及 `escalate_rules`，**立即停止自主决策，升级给治疗师并留痕**。

这一个设计带来三重收益：

- **合规**：Agent 从不自主开具或修改医疗处方，只在持证治疗师预设的范围内调节强度。作品定位为「康复训练依从性管理与远程随访工具」，不是医疗器械，不宣称疗效、不做诊断。
- **技术**：这是一个有状态、有约束、有工具调用、有升级路径的真 Agent，不是问答机器人。技术性 25% 的主要落点。
- **可解释**：每一个决策都能追溯到「治疗师设定的哪条规则 + 当天的哪个数据」。答辩时评委问「凭什么今天让他少做 5 个」，答得出来。

### 系统架构

```
┌─ 感知层（Agent 的工具，不是 Agent 本身）
│    MediaPipe Pose 端侧姿态估计 → 关节角度、动作幅度、完成计数
│    代偿检测：耸肩（肩峰上抬）、躯干侧倾、健侧代偿
│    自动开始/结束：人进入取景框并站定即开始，无需点击
│
├─ 决策层（LLM Agent，核心）
│    输入：处方边界 + 今日实测数据 + 历史趋势 + 患者自述（疼痛/疲劳/情绪）
│    输出（结构化 JSON）：今日方案 / 强度调整 / 话术 / 是否升级 / 决策依据
│    知识：康复指南 RAG + 训练动作库 + 该患者历史
│
├─ 交互层（无障碍设计，见下）
│    输出：语音播报（适老措辞 + 方言）+ 大字 + 高对比
│    输入：以视觉为主，语音仅作补充
│
└─ 协同层
     治疗师 Web 端：设边界、看周报、处理升级
     家属端：今天练了没有、练得怎么样
     一名治疗师同时管理数十名居家患者
```

### 四个针对「用不了 App 的人」的设计决策

**1. 输入用视觉，输出用语音——一个刻意的反转。**

其他产品用语音做输入（「说『开始』」）。但卒中患者有构音障碍，说不清话，通用 ASR 对这类语音识别率极低。所以本产品**不把语音当控制通道**：摄像头看到人站到位置就自动开始，做完一组自动计数，训练结束自动上报。语音只负责输出指导和鼓励。

这个设计不是取巧，是对目标用户真实能力的正确假设。也是能在答辩时讲清楚、别人一听就点头的那种设计。

**2. 零点击。** 偏瘫患者一只手要扶东西，另一只手拿不稳手机还要点屏幕。全流程不需要任何点击操作。

**3. 端侧运行、离线可用。** MediaPipe 本身就是端侧模型，姿态数据不出手机，只上传结构化结果（角度、次数、质量分）。农村网络差也能练，同时天然规避了「把患者的身体视频传上云」的隐私风险——这一条在材料里要写明，是加分项。

**4. 方言 + 适老措辞。** 不说「请完成肩关节外展 15 次」，说「胳膊慢慢往上抬，抬到这里就行，我数着」。措辞由 Prompt 控制，方言由 TTS 音色控制。

### Prompt 体系（原文硬性要求，要成体系而不是贴几段话）

| 模块 | 设计意图 |
| --- | --- |
| 角色与边界 | 明确身份是「治疗师的执行助手」，绝不开处方、不做诊断、不评价预后 |
| 处方边界注入 | 把 treatment envelope 的 JSON 结构化注入，明确哪些参数可调、可调范围 |
| 今日数据注入 | 实测角度/次数/质量分/代偿次数 + 患者自述疼痛与疲劳 + 近 7 日趋势 |
| 决策输出 Schema | 强制 JSON：今日方案、强度调整值、调整理由、话术文本、是否升级、依据引用 |
| 升级策略 | 触发 escalate_rules 时的固定动作与话术，禁止自行安抚 |
| 适老话术规范 | 短句、口语、不用医学名词、每次只说一件事、允许重复 |
| 少样本示例 | 3–5 组真实场景（进步/退步/疼痛/连续未练/情绪低落） |

### 评测（把实用性做成可量化的）

| 指标 | 对照 | 本产品 |
| --- | --- | --- |
| 关节角度测量误差 | 治疗师量角器读数 | 平均绝对误差 __° |
| 代偿检测准确率 | 治疗师逐帧标注 | __%（30 组动作） |
| 决策与治疗师一致率 | 治疗师对同样数据独立判断 | __%（**这是最有说服力的一项**） |
| 升级触发准确率 | 应升级场景是否全部命中 | __%（漏报为严重失败） |
| 训练依从性 | 使用前 __ 天/周 | 使用后 __ 天/周 |
| 单次训练无人协助完成率 | 现有 App 对照 | __% |

第三项「决策与治疗师一致率」是全作品最关键的证据：它直接回答「AI 凭什么替治疗师做日常判断」。找 2–3 位康复治疗师，给他们同样的患者数据做盲判，与 Agent 输出比对。样本不用大，30 组即可，关键是方法可信。

## 五、三天内的 MVP 边界（今天是 8/22，校内截止 8/25）

**必须砍到这个范围，多一点都做不完：**

- 训练动作**只做 2–3 个**：坐位肩关节外展、坐位伸膝、坐站转移。每个动作只做 1–2 项代偿检测
- 姿态估计直接用 MediaPipe Pose，不训练模型，角度计算 + 阈值规则
- Agent 用低代码平台或直接调 API + 结构化输出约束，不做复杂框架
- 治疗师端只做三个页面：设边界、看周报、处理升级
- 方言先做一种（长沙话或本地方言），TTS 现成音色即可
- 被试 3–5 人，30 组动作评测，2 位治疗师盲判

**必须保住的三样东西**（缺一件作品就垮）：可运行的程序 + 处方边界与升级机制的完整演示 + 决策一致率数据。

## 六、5 分钟演示视频的杀手镜头

| 时间 | 内容 |
| --- | --- |
| 0:00–0:30 | 4.4 万 vs 4.6 亿这组数字；一位出院患者在家对着手机不知道怎么练 |
| 0:30–1:00 | 治疗师 Web 端设定处方边界（不是固定处方，是可活动区间） |
| 1:00–2:00 | 患者站到镜头前**自动开始**，全程零点击；语音方言指导；完成计数 |
| **2:00–2:40** | **杀手镜头**：患者做肩外展时耸肩代偿 → 立即语音「肩膀放松，别抬肩」→ 患者调整 → 判定转绿。这 40 秒讲清楚了和「播放教学视频」的本质区别 |
| 2:40–3:20 | **第二杀手镜头**：患者说「今天有点疼」，Agent 当场把目标角度从 70° 降到 55°、组数减少，并说明理由；随后疼痛加重触及阈值 → **Agent 停止自主决策，升级治疗师，界面留痕** |
| 3:20–4:10 | 架构图 + Prompt 体系 + 端侧运行（拔网线继续可用）+ 后台代码/配置速览 |
| 4:10–4:50 | 决策一致率与代偿检测准确率数据表；治疗师端一人管多名患者的看板 |
| 4:50–5:00 | 合规声明（不做诊断、不宣称疗效、处方由持证治疗师制定）+ AI 生成内容标识 |

## 七、合规红线（医疗方向必须写进材料）

1. **定位为依从性管理与远程随访工具，不是医疗器械软件。** 不做诊断、不宣称疗效、不自主生成或修改医疗处方。竞品「对练」在应用商店页面就是这么声明的，这是行业通行做法，照做。
2. **训练方案必须由持证康复治疗师制定**，Agent 只在其设定边界内调节强度。
3. **升级机制不可绕过**：疼痛超阈、质量骤降、连续未练一律停止自主决策并通知人。漏报比误报严重得多，阈值宁可保守。
4. **知情同意 + 隐私**：受试者签署知情同意书；姿态数据端侧处理，原始视频不出设备、不上传；材料中人脸打码、姓名化名。
5. **不做心理疏导**，情绪低落只做识别与转介，不由 AI 安抚。
6. AI 生成内容按国家标准显著标识。

## 八、如果拿不到康复专业资源怎么办

这个方案的门槛在于需要**康复治疗师参与**（设定处方边界、做盲判评测）和**真实患者被试**。学校若有护理、康复治疗技术、医学相关专业，直接对接；否则走降级路径：

**同一套技术架构，把定位从「康复治疗」改为「老年防跌倒功能训练」。**

- 不涉及医疗，合规门槛大幅降低
- 被试从患者换成离退休处的老人，可及性高得多
- 「专家边界」从康复治疗师换成体育教师或社区医生
- 市场依然真实：跌倒是老年人重大公共卫生问题，防跌倒训练（下肢力量、平衡、步态）有明确的循证方案
- 技术栈、Agent 架构、Prompt 体系、演示脚本**一行都不用改**
