# 《学径AI》方案评估与改进

> 对「课前诊断 / 课中分层 / 课后间隔复习」这套方案的评估。
> 结论：**方向可行，但有一处结构性缺陷、一处心脏空缺、一处演示方式必须改。**
> 核心引擎代码在 `prototype/learning_core.py`，31 个单元测试全部通过。
>
> **先读第零节的表述纪律。** 单元测试验证的是引擎规则按设计稳定运行，不是学习效果；
> 所有掌握度与复习间隔都是占位参数下的**估计值**，不得表述为科学结论。

## 零、表述纪律（写进任何参赛材料之前先读这一节）

这套引擎产出的每一个数字都来自**未经真实数据校准的占位参数**。以下三组表述必须严格区分，
混用会在答辩时被一击命中，也触及组委会「严禁弄虚作假」的红线。

| 不能这样写 | 必须这样写 |
| --- | --- |
| 31 个测试证明学习路径科学有效 | 31 项单元测试验证了引擎规则、边界条件与决策逻辑按设计稳定运行 |
| 学生掌握度 98.4% | 掌握度**估计值** 98.4%（占位参数下）；学生端只展示「稳定掌握」等档位 |
| 三次独立答对后第 7 天复习是科学间隔 | 这是当前保守排期规则计算出的**原型排期结果**，正式应用需按真实答题数据校准 |
| 采用 FSRS 算法 | 遗忘曲线采用 FSRS 的**幂律形式**；稳定度更新是本项目自定义的保守规则，**不是 FSRS 算法** |
| 系统提升了学习效果 | 小规模探索性试用结果（报告人数、题数、独立答对比例、提示使用分布等过程指标） |
| 教师整理知识图谱从 40 分钟降到 6 分钟 | 待实测目标；必须真实计时后才能写入材料 |

定位语同理。「它判断你是不是真的会了」承诺过强，改为：

> **它不只看你是否答对，还估计你在多大程度上独立答对。**

需要更短的口号时用这句——同样锋利，但严格为真：

> **答对，不等于独立答对。**

## 一、这份方案里判断正确的部分

不是客套，这几条确实抓准了：

**1. 分级提示 + 记录提示依赖度 —— 这是全案最好的想法。**

「答对但依赖完整提示，不能直接标记为已掌握」是一个真实、可计算、且有学术基础的信号。智能辅导系统领域把「学生一路点到看完整解答」称为 bottom-out hint，通行做法就是**把它当作错误来记**。这一条本身就足以把作品和所有「AI 答题网站」区分开。

**2. 路径引擎与 AI 模型分离，关键决策不交给大模型。**

这个架构判断是对的，而且和 `docs/07` 里《复途》的结论完全一致：**确定性引擎独占安全与路径决策，大模型只生成内容。** 两个作品能收敛到同一个设计模式，说明这不是巧合而是这类系统的正解。

**3. 明确否掉「严格遵循艾宾浩斯遗忘曲线」。**

这一条抓得准。艾宾浩斯的实验材料是无意义音节，「第 1/2/4/7 天复习」是民间口诀不是科学结论。答辩时如果写了「遵循艾宾浩斯曲线」，遇到懂行的评委就是自曝其短。改成「结合间隔练习与检索练习原则，依学生实际表现动态排期」是专业的表述。

**4. 不做排行榜。** 排行榜对基础薄弱学生是净伤害，而这个产品的价值主张恰恰是帮薄弱学生。做排行榜会自相矛盾。

**5. 缩小到一门课、一个单元、5–8 个知识点。** 范围判断正确。

**6. 不做大而全的 AI 学习平台。** 与 `docs/01` 的结论一致——大而全在两个赛道都吃亏。

## 二、五个问题，其中三个必须改

### 问题 1：这是全省最红海的主题（结构性逆风，无法靠设计消除）

`docs/01` 里已经两次标注过：「AI 备课 / AI 批改 / AI 学情分析」是撞车最严重的方向。数智伴学·教育助教几乎是三个赛道里同质作品最多的一格——湖南的中小学教师、职业院校师生基数极大，学生组 70 个奖项分摊到三个赛道，其中教育类作品的密度会远高于其他题材。

赛道三创新性占 **25%**。评委看到第五份「AI 个性化学习助手」时的判断标准会和第一份完全不同。

**必须诚实面对的取舍：** 从《复途》（康复，在这个比赛里近乎孤例）转到《学径AI》，等于**用「稀缺性」换「可落地性」**。

那么这个交换值不值？在只剩两天半的前提下——**值。** 因为：

- 学径AI 的被试就在教室里，《复途》需要康复治疗师和真实患者
- 教育场景的领域知识你本来就有，不需要临床背书
- 无医疗合规风险

所以「更稳」这个判断在**可交付性**上是对的，只是要清楚代价在**创新性得分**上。对冲办法见下面第三节。

### 问题 2：方案承诺减负，但冷启动是净增负担（最容易被评委一击命中）

把流程摊开看：教师导入教学目标和课程材料 → 确认知识点 → 审核 AI 生成的诊断题 → 审核分层练习 → 查看学情 → 调整。

**要让系统跑起来，教师得先把一个单元的知识点、前置关系、教学目标、题库标注全部录进去。** 对一个只想省时间的老师，这是先付出一大笔前期成本。

而赛道三教师组的评审要点原文是「**减轻教师负担的实际效果**」。一线教师评委的第一个问题必然是：

> 「我要用它，得先花多久把知识点录进去？」

**改进（这是最有价值的一条）：让 Agent 从教师现有材料自动抽取知识点图谱与前置关系，教师只做确认和微调，而不是从零录入。**

输入就用老师电脑里已经有的东西：课件 PPT、教案 Word、往年试卷、教材目录。输出是一张候选知识点图（含前置关系与重要性建议），教师在界面上拖动增删确认。

这一步同时解决三件事：真正做到减负而不是喊减负；这是 LLM 真正擅长的任务，构成实打实的技术含量；而且它给了「从零到可用」一个可量化的前后对比——手工整理一个单元的知识点图谱耗时 vs 自动抽取加确认耗时。

**这组数字必须真实计时后才能写进材料**，不能预设。取证方式是双机计时录屏：一台录老师手工整理，一台录上传材料后确认修改。「使用前」那段一旦系统上线就补不回来，属于最优先要抢的素材。

### 问题 3：心脏空缺 —— 掌握度到底怎么算，方案没说

原方案写了「路径引擎：确定掌握程度、任务难度、复习时间和进阶规则」，但没有说掌握度用什么方法估计。如果实现成「答对 +1、答错 −1」，评委一问「凭什么说他掌握了 70%」就露底了。这是整个产品的心脏，不能含糊。

**改进：用成熟模型，不自创，也不让大模型猜。**

| 模块 | 选用 | 理由 |
| --- | --- | --- |
| 掌握度估计 | **BKT**（Bayesian Knowledge Tracing，Corbett & Anderson 1995） | 四参数（先验 / 学习率 / 猜对率 / 失误率），每个参数都能用一句话向教师解释，几十行可实现，**不需要训练数据** |
| 不选 | DKT（深度知识追踪） | 需要大规模历史答题数据。三天内没有数据可训，用它等于自欺 |
| 遗忘曲线 | **FSRS 的幂律形式** R(t) = (1 + t/9S)^−1 | 目标保持率 0.9 时复习间隔恰好约等于稳定度 S 天 |
| 稳定度更新 | **本项目自定义的保守规则**（不是 FSRS 算法） | 独立成功增长最多、依赖提示打折、失败回落；**并按成功次数限幅**，见下 |

**关于复习间隔的一处自我纠正。** 我最初的实现让稳定度无上限连乘，三次独立答对就排到
**29.1 天**之后复习——这个数字不是 BKT 或 FSRS 推导出来的，是我自定的增长系数
（独立答对 ×2.4，再按掌握度放大）连乘的结果，对一个刚学的知识点过于激进。

已改为**按证据量限幅**：独立成功 1/2/3/4 次时，复习间隔上限分别为 1/3/7/15 天，
超过 4 次后不再限幅。修正后同样三次独立答对的间隔是 **7.0 天**。

这个限幅不是「第 1/2/4/7 天」那种固定复习表——它的依据是**不确定性**：只观测到一两次成功时，
把间隔外推到几十天缺乏根据。而且它不会抹平个体差异：依赖提示的学生增长慢、根本触不到上限，
失败则回落。实测中学生 A 触顶 7 天，学生 B 只有 1.5 天（`test_hint_dependent_student_hits_cap_later`）。

**关键衔接：BKT 天然能吸收「提示依赖度」这个信号。** 做法是用提示等级抬高该次观测的**等效猜对率**——提示越高级，答对越不能说明掌握；看了完整解答才答对，按 bottom-out 惯例记为未掌握证据。

这一步把原方案里最好的想法接到了成熟模型上，于是既有创新点又可解释。实测效果（`prototype/learning_core.py`，先验 25%）：

| 提示级别 | 等效猜对率 | 答对后掌握度 |
| --- | --- | --- |
| 独立作答 | 0.20 | 25% → **67.2%** |
| 提醒知识点 | 0.40 | 25% → 53.1% |
| 给解题方向 | 0.60 | 25% → 45.3% |
| 展示相似例子 | 0.80 | 25% → 40.4% |
| 看完整解答 | — | 25% → **21.3%**（低于作答前） |

### 问题 4：「两名虚构学生」的演示不能用（这条最危险）

原方案建议用两名虚构学生做对比演示。**在这个比赛里用编造数据演示是高风险的。** 组委会文件明确「严禁营销炒作、弄虚作假」，复评「注重作品实用性」且可能有「场景模拟演示」。虚构学生一旦被问「有真实学生用过吗」，实用性（20%）直接失去举证。

**改进：用真实学生，而这恰好是这个方向最大的优势。**

找 10–20 名真实学生做一个单元的课前诊断，一两天就能完成——比找卒中患者容易一个量级。原方案想要的对比演示，完全可以**从真实数据里挑两个学生**呈现，而不必编造。

而对比效果不需要编——引擎算出来的差异比编的更有说服力。实测（**表格标题须写作「同一占位参数下，提示依赖对引擎估计结果的影响」**）：两名学生**三题全对，唯一差别是提示依赖**，

| | 掌握度估计 | 学生端档位 | 复习间隔 |
| --- | --- | --- | --- |
| 学生 A：独立答对 ×3 | **98.4%** | 稳定掌握 | **7.0 天** |
| 学生 B：靠例子提示答对 ×3 | **64.2%** | 需巩固 | **1.5 天** |

同样的「三题全对」，掌握度估计差 34.2%，复习间隔差 5.5 天，学生端看到的档位也不同。**这一张表就是整个作品最有说服力的一页**，它一句话说明了「答对不等于独立答对」。

注意学生端只显示档位（正在建立 / 需巩固 / 基本掌握 / 稳定掌握），不显示「你已掌握 98.4%」——参数未校准时，那种精度是虚假的。概率值只在引擎内部和教师端使用，且教师端标注为「掌握度估计」。

**真实学生试用能报告什么、不能报告什么。** 两天内可以真实报告的是过程指标：参加人数、完成题数、独立答对比例、各级提示使用次数、系统触发前置补缺的次数、完成时长、简短可用性反馈。**不能**声称提高了学习效果。即便做了前后测，也只能称「小规模探索性试用结果」，不能称对照实验。展示两个学生案例时，必须**先报告全体数据再展示匿名个案**，不能只挑最戏剧性的两个而隐去整体。

### 问题 5：学科选择，四个例子里只有一个真正合适

| 原方案例子 | 评价 |
| --- | --- |
| 数学：一元二次方程 | K12 题材，与职业院校身份不符，且是同质作品最集中的选题 |
| 英语：单元词汇与阅读 | 词汇记忆是 Anki 这类工具的成熟地盘，差异化最弱 |
| **计算机：Python 条件与循环** | **最优。** 答案可自动判定，而且**可以真的执行学生代码** |
| 职业教育：实训操作规范 | 辨识度最高、最契合职教身份，但答案难自动判定，三天内风险大 |

**推荐 Python 条件与循环，理由是可执行判题。**

学生提交的代码可以直接跑：语法错、逻辑错、边界条件错（比如循环少跑一次）都能由**运行结果**判定，而不是由大模型猜。这把「错因识别」从「大模型说的」变成**可验证的事实**，可信度和技术含量同时上一个台阶。答辩时评委问「你怎么知道他是边界搞错了而不是不会循环」，答案是「跑出来的，输入 5 应输出 5 行他输出了 4 行」。

这也天然契合职业院校身份和「数字技能」这个大赛主题本身。

## 三、对冲撞车劣势的三个动作

既然主题红海无法回避，就靠这三点在评委面前跳出来：

**1. 定位语要锋利，不要写成功能列表。**

原方案的定位语是「通过动态诊断、分级提示、掌握状态建模与个性化间隔复习，构建课前课中课后的连续学习路径」——这是功能罗列，评委记不住。

建议改成一句能被复述、且严格为真的话：

> **它不只看你是否答对，还估计你在多大程度上独立答对。**

需要更短的口号时：**答对，不等于独立答对。**（同样锋利，但不承诺「判断你是不是真的会了」这种做不到的事。）

**2. 把「不重复练已掌握的内容」做成可量化的省题率。**

这个产品真正的卖点不是「学得更多」，而是「少做无用题」。所以要给出数字：同一个教学目标下，**统一布置需要做 N 题，本系统平均只需 M 题，省题率 X%，且后测成绩不低于对照组。** 这是实用性（20%）最硬的证据，也是唯一能量化「让每一分钟学习更有效」这句话的方法。

**3. 教师侧必须有减负的实测前后对比。**

如果报教师组，评审要点就是「减轻教师负担的实际效果」，这和赛道二的方法论一样——必须有实测数据：

| 环节 | 使用前 | 使用后 | 取证 |
| --- | --- | --- | --- |
| 整理一个单元的知识点与前置关系 | ___ 分钟 | ___ 分钟 | 计时录屏 |
| 出一套分层练习 | ___ 分钟 | ___ 分钟 | 计时录屏 |
| 统计班级学情 | ___ 分钟 | ___ 分钟 | 对照原 Excel 流程 |
| 判断课堂先讲哪个共性问题 | 凭印象 | 按未达标比例×重要性排序 | 系统截图 |

没有这张表，「减负」就是一句空话。

## 四、核心引擎的实现状态

`prototype/learning_core.py` 与 `prototype/test_learning_core.py`，31 个单元测试全部通过。

**这些测试验证的是引擎规则、边界条件与决策逻辑按设计稳定运行**——即代码没有逻辑错误、参数越界会被拒绝、各条规则在设计的触发条件下正确触发。它们**不**证明掌握度估计等于学生真实掌握概率、也不证明排期是最优复习时机、更不证明使用系统能提高成绩。那需要真实数据校准和对照研究，不在两天的射程内，也不必在参赛材料里声称。

| 能力 | 实现 | 验证 |
| --- | --- | --- |
| 掌握度估计 | BKT 四参数后验更新 + 学习转移 | 答对升 / 答错降；退化参数（猜对率+失误率≥1）被拒绝构造 |
| 提示依赖度作为证据 | 提示等级抬高等效猜对率；bottom-out 记为未掌握 | 五级提示的掌握度严格单调递减；差值 > 0.2 保证信号有意义 |
| 「全对但不算掌握」 | 三次靠例子提示答对，掌握度估计仍低于阈值 | 有测试守护 |
| 学生端档位展示 | 四档文字，不暴露概率；达阈值但独立成功不足只给「基本掌握」 | 靠提示答对者永远拿不到「稳定掌握」 |
| 掌握学习（前置门控） | 递归找最底层未达标前置 | 多层薄弱时先补最底层，不就近处理 |
| 连续答错回退 | 连续答错 ≥3 次即回退前置，不继续刷同类题 | 实测第 3 次答错时切换，且优先于常规到期复习 |
| 间隔复习排期 | 幂律遗忘曲线 + 自定义保守稳定度更新 | 到期日的可提取概率精确等于目标保持率；独立答对使间隔单调延长 |
| **证据量限幅** | 独立成功 1/2/3/4 次时间隔上限 1/3/7/15 天，之后放开 | 理想学生前三次恰为 1/3/7 天；依赖提示者触不到上限；证据充分后突破限幅 |
| 复习优先级 | 重要性 × (1 − 可提取概率) | 同等遗忘程度下重要性高者排前 |
| 班级共性问题 | 按 未达标比例 × 重要性 排序，并单列「重度依赖提示」人次 | 靠提示答对的学生必须留痕，否则教师会误判已掌握 |
| 大模型边界 | 路径决策全部由引擎产出，每条带可追溯理由 | 每个决策的 reason 含具体数值 |

「连续答错回退」这条是**单元测试逼出来的**：原方案文字里写了这条规则，我第一版实现漏掉了，测试跑出来才发现引擎只会一直说「继续练」。这类漏实现在演示视频里完全看不出来。

## 五、时间现实与最终建议
